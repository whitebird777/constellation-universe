# Beta Test Plan

## 1. Beta 测试目标

验证 StarUniverse MVP 在真实用户手中的核心假设：
- 用户是否愿意每天回来看看自己的星球
- 产品调性是否能与目标用户建立情感连接
- 核心循环（Daily + Growth + Timeline）是否成立

## 2. 测试范围

| 项目 | 说明 |
|------|------|
| 人数 | 5-10 人 |
| 周期 | 7 天 |
| 平台 | 微信小程序 |
| 版本 | Beta 0.1 |

## 3. 测试流程

### Day 0：启动
1. 用户接收小程序邀请
2. 独立完成首次体验（无引导、无说明）
3. 记录首次体验时长

### Day 1-7：日常回访
1. 用户自行决定何时打开
2. 不发送推送、不催促
3. 观察自然回访频率

### Day 7：反馈收集
1. 一对一简短访谈
2. 填写反馈表单

## 4. 关键观察指标

| 指标 | 定义 | 目标 |
|------|------|:---:|
| 次日留存 | Day 1 回访率 | > 40% |
| 7 日留存 | Day 7 仍回访 | > 20% |
| Timeline 查看率 | 至少查看一次 Timeline | > 60% |
| 探索点击率 | 至少使用一次探索 | > 50% |
| 平均停留时长 | 星球页停留时间 | > 30s |
| 重新开始率 | 使用重置功能 | < 10% |

## 5. Bug 收集规范

- 所有 Bug 记录到 CHANGELOG.md Known Issues
- 格式：编号 / 页面 / 描述 / 复现 / 优先级
- 阻塞级 Bug 24h 内修复

## 6. 用户反馈记录模板

```
用户编号：
首次体验时长：
Day 1 是否回访：
最喜欢的部分：
最困惑的部分：
是否愿意继续使用（1-5）：
一句话感受：
```

## 7. Beta 结束标准

- 收集 5+ 份完整反馈
- 无阻塞级 Bug
- 明确是否进入下一阶段开发
